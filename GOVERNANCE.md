# SharBo Globo Governance

SharBo Globo currently uses a **maintainer-led governance model**.

## Project maintainer

The repository owner (`sidphoto`) is the current project maintainer and has final responsibility for:

- public project scope and roadmap;
- merge and release decisions;
- source-available and commercial licensing decisions;
- trademark and branding permissions;
- security response;
- public/private architecture boundaries;
- appointment of future maintainers.

## Contributors

Contributors may propose code, documentation, translations, tests and generic framework improvements through pull requests. Contributions are reviewed for technical quality, licensing compatibility, security and adherence to the public data boundary.

A contribution is not accepted until it is merged by a maintainer.

## Production source intelligence

Production source registries, source-selection strategy, trust weights, evidence corpus and commercial configuration are not community-governed assets of the public repository. Decisions about those proprietary assets remain with the project owner or the operator of the relevant commercial deployment.

## Decision process

For public repository changes, maintainers consider:

1. user value;
2. data integrity and explainability;
3. source-data confidentiality;
4. security;
5. maintainability;
6. compatibility with the licensing and commercial model.

Maintainers may decline technically valid contributions that conflict with project direction, commercial boundaries or brand strategy.

## Future maintainers

The governance model may evolve if the contributor community grows. Any future maintainer role, voting structure or delegated authority will be documented here.
